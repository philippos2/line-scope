# 2台の加工機トラブルのデモデータ構成

この文書はデモの架空条件を説明する。業務仕様の正本は[文書入口](../deliverables.md)を参照する。実装・確認状況は[ロードマップ](../roadmap.md)で管理する。

## 調査する状況

第1加工機M-204は主軸異常、第2加工機M-208は冷却系異常により停止している。これは初期投入する架空状態であり、実設備からの自動検知ではない。

| 設備 | 作業・工程 | 影響候補の製品 |
|---|---|---|
| M-204 | OP-30→OP-40、P-10→P-20 | P-100（共有）、P-200（個別） |
| M-208 | OP-50、P-30 | P-100（共有）、P-300（個別） |

2台とも共通電源R-02に依存する。共通電源への依存から故障原因が電源だとは断定しない。M-208→M-204の代替候補関係は残るが、M-208も停止しているため利用可能な代替とは扱わない。

製品への到達は影響候補であり、実際の生産停止量や損失額を確定するものではない。損失の推定には別途、範囲・期間・加算条件・出典の揃った登録根拠が必要になる。

## 初期投入と再開の原則

このシナリオは旧Graphデモと区別して明示的に選択する。新しい専用環境で最初のGraph Rebuild前に投入する。既存環境に不足行を追加して整合させる移行機能ではない。

再実行で既存の設備状態・名称・versionはリセットしない。関係の編集や他の関係セット、構築済みGraphへ新規データを追加する操作は拒否する。シナリオの初期状態へ戻す必要がある場合は、新しい専用環境を使う。継続デモのvolume削除や既存状態の上書きはしない。

専用環境の構築時は[通常環境の起動](../getting-started.md#通常環境の起動)にある `seed-demo-graph` を次のコマンドに置き換え、その後にGraph Rebuildを実行する。新規の専用project・私有env・portを準備し、既存サービスへ向けない。

```sh
docker compose run --rm migrate linescope seed-demo-incident
```

現在の追加実装は初期Graphデータまで。損失入力・集計と一連のUIはP1・P2の残項目であり、このコマンドだけで完成シナリオにはならない。
