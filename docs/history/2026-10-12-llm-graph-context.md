# 実LLM Graph応答のコンテキスト設定

仕様正本ではなく調査・変更記録。

#166の実LLM probe失敗をOllama serviceログと照合した。2026-10-12 14:32:33 / 14:33:55 JSTに、10880 / 10876 tokenの要求が8192 tokenのコンテキスト上限を超えると記録されていた。疎通不能と判断して無条件retryする問題ではなく、Graph Toolの結果を含む入力サイズが固定枠を超えたケースだった。

OllamaClientのcontext_tokensをサーバ設定から注入し、既定16384とする。Settings、環境変数、Compose、bootstrapを接続し、正整数以外は拒否する。model具体選定・私有.env・LLM60秒予算・Tool権限・Graph上限・回答生成上限は変更しない。LLM生応答やproviderエラー本文を外部へ公開しない。

この設定は入力が無制限に収まる保証ではない。大規模GraphのLLM向け表示量・会話履歴予算の扱いは別途検討が必要。サーバEvidenceを削ることで見かけ上合格させない。実測結果はPRへ記載する。

16384への変更直後のモデル再読込を伴う試行では入力超過エラーは解消したが、Agentの60秒上限に達した。コンテキスト拡大だけで応答時間の保証にはならない。

読み込み済みモデルでも60秒に達したため、AgentのLLM入力でdataとEvidenceに同一代表経路が二重に含まれる箇所を改善した。LLM入力のEvidenceコピーから同一経路だけを省き、data内の所在を明記する。元のサーバ結果・HTTP Evidenceを変更しない。経路が異なる場合は省かない。入力枠拡張と同じGraph応答の問題に対応する変更であり、実行予算の緩和は行わない。
