# 複数除外条件を維持する代替評価

仕様正本ではなく、実装チェックポイントの記録。

正本domain-model §15.1 / §15.4に従い、内部Applicationの代替評価へ全除外集合を渡す経路を追加した。除外対象自身に加え、ほかの明示除外も候補と候補自身の必須依存へ適用する。設備RUNNINGは除外条件を解除する根拠にならない。型付き除外集合は状態adapterのI/O前に検証する。

SubstituteSelectionへ評価時の全除外集合をimmutable frozensetで保持する。重要対象の除外後成立を計算する際、置換対象IDだけでなく除外集合も完全一致させる。単一除外の評価を複数除外へ、追加除外がある評価を少ない除外へ流用することを拒否する。これは内部評価契約であり、公開ToolのDTO変更ではない。

追加8テストと関連75テスト、計83テストをDocker内で実行した。実PostgreSQL / Neo4jからのRUNNING観測でも除外候補を利用不可とすること、不正除外入力で状態I/Oしないこと、除外集合の増減による評価流用拒否を検証した。既存INCOMPLETE試験のfixtureを同じ全除外集合で候補評価する形へ修正し、assertionは維持した。

AC-G05 / G06 / G09、T-R14 / R15の複数除外意味論を支えるが、複数重要対象・全除外のGraph収集／共有予算、単一状態観測の全体調整、代表経路と公開DTO、Tool / API / Agent接続は後続。現在のRepositoryだけから評価条件を追跡できるよう、この記録と型を維持する。
