# H7：明示選択の登録照会の設計案

開発者は81回の受入未達の報告後、「それで良い。続けよ」、検討中にも「そうせよ」と指示した。直前に提案した閉じた選択方式の具体化として扱い、新しい契約・26件の追加試験の実装承認へ広げていない。

## 読み取りで確認したこと

- Appの質問送信と確認後の結果は同じresultへ入る。原問と別の照会を分けるため、選択結果を別state・別表示にする必要がある。
- AgentInputは新しいread_selectionを拒否する。既存POST /agentに型付き入力・出力を追加する契約案であり、新HTTP経路が不要だから契約変更もない、とはいえない。
- AgentApplicationは通常要求で書込再送照合・Prepare認識を経由し、ReadAgent生成はLLMの有無に依存する。型付きReadはこれらから独立させる必要がある。
- scoped_readsはMAINTENANCE topicで記録と計画の両方を取得する。選択したfieldだけの参照に絞る必要がある。
- grounded_answerは質問本文の語句から属性表示を絞る。元の問いを再解釈せず、型付きで選んだfieldから表示範囲を決める必要がある。questionを消して全属性を表示する近道は採らない。
- LLM由来READ_SCOPEの受理を残すと既知の誤誘導経路が残る。新画面で隠すだけでなく、旧保留の受理もサーバで失効させる案にした。
