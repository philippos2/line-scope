# SPOF探索の公開前入力境界

仕様正本ではなく内部実装チェックポイント。domain-model §15、api-tools §17 / §22に従う。

SPOFの重要対象と任意候補集合を、認証済みContextと固定サーバ時刻・上限で検証する内部Application処理を追加した。候補省略は後続の自動収集、明示空集合は自動収集しない指定と区別する。重要対象は空不可、candidate_nodesのNULLも拒否する。

UUID正規化後の集合内重複を拒否し、全明示入力の和集合へnode上限を適用する。配列間の重なりは保持し、対象自身の候補除外は対象別評価で行う。relation_types・timeout・認証主体の上書きを拒否する。

Tool登録・HTTP・Agent公開はまだ行わない。次工程は単一世代・共有予算での候補収集、一回の正本状態観測、候補ごとに一要素を除外する評価、Evidenceと公開契約の接続。全候補を同時除外する代替分析とは意味が異なるため、その評価結果を流用しない。
