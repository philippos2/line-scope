# 除外対象に対する一段代替候補の集約

仕様正本ではなく、実装チェックポイントの記録。

正本domain-model §15.1 / §15.3 / §15.4に従い、直接代替候補の独立評価とOR集約を追加した。呼出元がactive / effectiveなCAN_SUBSTITUTEのsourceを候補として取得し、方向・正本状態・必須閉包・探索予算を確認する。純粋計算は候補を検索せず、連鎖置換もしない。

仮想除外の対象自身を必ず除外集合へ追加し、その他の除外も維持する。対象自身・異種候補・不正入力は拒否。重複候補を型付きIDで一意化・ソートし、全候補の評価結果を保持する。候補自身の依存を免除せず、無関係な稼働設備を代替として取り込まない。

完全な評価ではAVAILABLE候補がUNKNOWNの運転状態より優先する。AVAILABLEなし・UNKNOWNありは未確定。完全な空集合だけUNAVAILABLEとし、探索不完全や候補の必須閉包欠落はUNKNOWN・complete=false。必須循環が評価に含まれる場合は循環成立を仮定せずUNKNOWN・MANDATORY_CYCLEとし、探索のcompleteと判定不能を分ける。単なる未知の運転状態と、構造循環による判定不能を同一視しない。

追加24テストでOR、順序と重複、対象除外、他の除外、連鎖置換なし、空集合、未知、不完全性、循環、過去時点、不正入力を検証した。AC-G05 / G09とT-R14 / R15の候補集約部分を支えるが、Graph検索・関係Evidence、重要対象の全AND成立、除外前成立確認、SPOF、Tool / API接続は後続。能力・安全性・経済性は判定しない。
