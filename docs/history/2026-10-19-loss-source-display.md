# 損害額の出典の重複表示修正

## 原因と対応

開発依頼者がブラウザで出典の重複を発見した。経済入力の製品別incident_lossesに同じsourceがあり、UIがmapとjoinでそのまま連結していた。データや損害額の計算の誤りではない。

同じ出典文字列を1回にまとめ、異なる出典がある場合は対応製品の名称・コードを併記するよう修正した。出典が複数製品で共通する場合も出典ごとにまとめる。登録内容・Backend・API契約は変更していない。

Frontendの他のjoin箇所も確認した。経路は順序とノードの連なりに意味があり、重複削除しない。未評価製品・不足キー等の列挙は同一出典の連結ではなく、今回の重複原因と同じ処理はなかった。

## 検証

- Docker内npm run check成功。関連単体19件成功。既存の表示モデル検証に共通出典・異なる出典のassertionを追加した。
- 実ブラウザ主経路で共通出典が1回のみ表示されることを検査した。既存の応答制御ケースでは出典だけを異なる文字列に置換し、製品との対応を検査した。登録データは変更していない。
- 5174番の専用Frontendのみ再構築した。5173番は変更せず、PR #265はDraftを維持する。
