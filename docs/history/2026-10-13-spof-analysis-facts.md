# SPOF候補の共有予算収集

仕様正本ではなく内部実装チェックポイント。domain-model §15、api-tools §17 / §22に従う。

重要対象別に必須上流候補を収集し、候補自身を除外した場合に必要な一段代替・候補の必須依存factsを同じ検証済みGraph read内で取得する。候補未指定は各対象の必須上流集合から収集し、明示空集合は自動収集しない。各重要対象自身はその対象の候補から除外する。

重要対象・明示候補・探索上流・一段代替を一つのdistinct node予算で管理する。代替facts収集には既存collectorへ共有予算を渡し、探索段階ごとにnode予算をリセットしない。対象自身の候補除外は対象別に維持する。全体の打切り理由を全候補へ伝達し、探索不完全な空候補を不存在の証拠にしない。

この処理は収集のみであり、候補の同時除外を評価しない。次工程で各候補の単独除外、単一PostgreSQL状態観測、対象別分類とEvidenceを接続する。Tool / HTTP / Agent公開・Business Scenario受入は未完。
