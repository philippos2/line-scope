# 常設部品の接続と業務シナリオに沿うUIの再設計

## 指示と修正した判断

- 開発依頼者は必要な全機能・部品を組み込んだ後に、UIを一連の業務シナリオへ沿って再設計するよう指示した。
- 代表API試験とCIの成功だけで全体100%・追加PR 0と報告したのは誤り。常設接続と利用者の操作体験を完成確認へ含め、ロードマップを訂正した。
- UI変更前に常設Qdrant、導入済みEmbeddingモデル、read／write keyの分離、文書取込みを追加した。既存DB資格情報とデータは保持。常設Frontendから実検索・引用表示PASS（source QDRANT、demo_only false）。

## 変更

- 左の工程ナビと対象設備表示、6工程の中央操作へ再構成。自由質問・処理原文は補助の折りたたみへ移した。
- 設備名・コード検索→対象選択→状態・下流の調査→比較→比較Evidenceと文書引用→入力登録・訂正→承認・実行と再比較をつなぐ。
- 比較Envelopeを親へ渡してEvidence工程へ保持。状態結果もGraph調査で失わない。変更後は旧結果の再取得を求める。
- 入力は4種類を切替え、対象変更時に編集componentを作り直して旧応答を破棄。接続解除・切替では対象・取得結果を消去する。
- 承認者は対象設備未選択でも工程6へ進み、要求IDから保存Snapshotを読み直せる。IDコピーと、元依頼者への接続切替案内を追加。
- Backendの業務ルール・認可・承認・実行の契約は変更していない。

## 初回の常設ブラウザ確認

ブラウザUIのみで10段階PASS。裏からAPIでfixture登録・承認・実行を代行していない。M-204選択13.2秒、状態取得9.5秒、下流6件の完全探索41.6秒。未選択比較は費用不明を保持。実Qdrantの引用1件を確認し、経済入力をUIで準備→manager2承認→manager1実行→再比較で修理300000 JPYを確認。browser runtime errorなし、390／768／1440pxでoverflowなし。

この結果は1代表シナリオの成功であり、全BSや全更新variant、任意自然文の精度を保証しない。最終sourceの結果・CIは確認後に追記する。
