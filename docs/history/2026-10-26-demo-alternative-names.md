# 質問欄の代替候補を名称で回答する

## 目的・制約・完了判定

開発者の『M-204の代替候補は？』への回答には件数だけで候補名がなく、質問欄で照会が完結していなかった。既存のGraph判定とEvidenceを維持し、代替関係の候補IDを既存設備Readで名称・コードへ解決して本文に出す。実際の代替運転・能力・安全・経済影響は未評価と同じ塊で明記する。他の質問処理、カタログ、DB、API契約は変更しない。

Graphの公開DTOのalternativesはexcluded_nodeとcandidatesを持ち、各candidateにentity_type/entity_id・structure・availabilityがある。質問対象との対応と型を確認してから名称を取得する。構造不成立や利用可否不明を、利用可能な設備へ読み替えない。探索不完全・候補0件・名称取得失敗を区別し、未知の名称を推測しない。

質問欄の下流・上流回答からも構造化結果への誘導だけを省く。既存rendererの既定表示は変えず、質問欄でだけ詳細リンクの文を抑止する。

## 実装前の追加試験（10ケース）

候補状態×探索完全性×名前取得を直積にせず、正常代表と失敗境界を各1件ずつ選ぶ。同じ実装の判定を試験で再計算せず、本文が質問へ直接答え、根拠の対象・値と一致することを確認する。

| ケース | 防ぐ失敗 |
|---|---|
| 成立・利用可能 | 件数だけで候補名がない |
| 成立・利用不可 | 構造成立を現在の利用可能と混同 |
| 成立・利用可否不明 | 不明を利用可能と断定 |
| 構造不成立 | 不成立を成立した候補として案内 |
| 候補0件・探索完了 | 登録関係の探索結果から物理的不存在を断定 |
| 探索不完全・候補あり | 不完全なのに候補を確定扱い |
| 探索不完全・候補0件 | 未取得を候補なしと断定 |
| 名称取得失敗 | 候補なしへ読み替え、名前を推測 |
| 名称Evidence不一致 | 根拠不整合の候補名を公開 |
| 除外対象不一致 | 別の設備の代替結果を公開 |

既存9観点の正常試験を維持し、代替fixtureを公開DTOに合わせる。新規観点・意味解析・単語別分岐は追加しない。実モデルを使わない。報告された原文は実APIに各3回送る。UIの構造変更はないが、5174番の質問欄の本文も実ブラウザで確認する。

## 文言の完全一致について

開発者の補足を受け、回答全文や一文の完全一致を受入条件にしない。試験は候補の名称・コード、構造上という限定、実際の代替運転の未評価、障害と候補なしの区別を確認する。未対応4問の本文一致は今回の非変更確認という観測結果で、恒久的な回答文の制約ではない。質問を受け付ける語彙カタログの範囲はこの補足から独断で拡張しない。
