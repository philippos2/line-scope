# UI再設計のレビュー準備

## 指摘と方針

PR #262 merge後の利用者確認で、設備探索を算定データに依存させた入口、依存関係の調査を別モードへ分離したこと、不自然な文言について指摘された。代表試験の成功をUI設計の妥当性として扱った判断を撤回する。機能実装の到達点と、利用者が自然に目的へ到達できるかは別に評価する。

開発依頼者から提示されたClaudeの指示書を基に、まず文書として設計を作り、Claudeの評価を受ける指示となった。Frontendには着手しない。

## 今回の成果物

[UI再設計案](../design/frontend-redesign-proposal.md)に、目的、画面構成、操作順、状態別表示、データ経路、責務、移行表、用語、UA-01〜08、判断待ちをまとめた。現行画面設計には案へのリンクだけを追加し、新設計へ置き換えていない。

現行APIとコードから、非LLM設備検索の経路が未決であることに加え、現行損害額算定は稼働中設備の仮想停止金額を扱わないことを確認した。候補すべての算定データ有無も一括取得できる契約ではないため、案では未確認と未登録を区別し、判断点として明記した。

## 変更しない範囲と次の工程

Frontendソース・Backendソース・API契約・データ・稼働サービスは変更しない。文書リンクと差分を確認し、実装のテストやサービス再起動は行わない。

次はClaudeと開発依頼者による設計評価。設備検索経路等の未決事項と設計の承認後に限り、実装を開始する。本書作成は実装許可ではない。
