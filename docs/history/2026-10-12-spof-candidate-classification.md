# 重要対象ごとのSPOF候補分類

仕様正本ではなく、実装チェックポイントの記録。

正本domain-model §15.1 / §15.4に従い、重要対象・必須上流候補ごとに、除外前成立と一段代替を含む除外後成立からSPOF / NOT_SPOF / INDETERMINATEを分類する純粋計算を追加した。対象自身は候補にできず、必須閉包外の要素はNOT_SPOF。複数重要対象は個別評価する。

除外前から構造不成立、必須循環、探索不完全、情報欠落がある場合はINDETERMINATEとし、新しい除外の原因へ帰属させない。除外後の成立維持はNOT_SPOF、代替を含めても不成立はSPOF、利用可能性未確定や候補探索不完全はINDETERMINATE。代替評価欠落を「代替なし」とせず、対象不一致の評価流用を拒否する。

before / afterの内部構造評価を保持し、後続のEvidence形成で分類理由を追跡できる形にした。呼出元が同一世代・時点・除外集合に基づくGraph／代替評価を提供する。稼働状態・容量・安全性を構造成立と混同せず、過去時点の現在利用可能性を推測しない。

追加20テストと関連145テストで、代替なし・利用可能代替・未知・元要素に依存する候補、対象別分類、除外前不成立、循環、情報欠落、不完全性、過去時点、対象自身と評価対象不一致を検証した。AC-G06 / G09とT-R14 / R15の分類計算部分を支えるが、Graph readerによる候補収集と予算管理、状態正本、代表経路・関係Evidence、Application / Tool / API接続は後続。公開契約や受入基準全体の完了とは扱わない。
