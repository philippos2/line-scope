# LineScope 開発ロードマップ

仕様の正本は[文書入口](deliverables.md)で選ぶ。本書は残る業務機能・受入条件・工程を管理する。PRやテストの件数を進捗率へ換算しない。

## 現在の進捗

**全体約70%（目安65〜75%）。完成間近という評価ではない。** 実ミドルウェアへの接続と、正式な業務入力・総合受入の完了は区別する。

| 利用できる業務経路 | 到達点・制限 |
|---|---|
| 設備調査・Graph・Evidence | 実PostgreSQL / Neo4jによる影響・上流・共通依存・代替構造・SPOFの代表経路。実際の能力・安全はGraphだけで認定しない |
| 文書検索・引用 | 実Embedding / Qdrantの登録・検索・引用・版更新・再構築の代表経路。一般検索品質は未受入 |
| 既存の承認付き更新 | 設備状態・保全・生産運用・依存関係の代表UI経路、別承認者・requester確定・拒否を検証。全variantの包括受入は残る |
| 正式経済入力 | #246・247 merge済み。登録・訂正・別manager承認・確定・計算・検索・画面・Agent Readの代表経路を検証 |
| 正式能力入力 | #248で登録・訂正・計算APIを実装。画面・Agent・実ブラウザの業務経路まで同PRへ統合中。未受入 |

既存デモ比較にはMOCK_FIXTUREの費用・能力・安全条件が残る。正式な経済入力はREGISTERED_INPUTとして分離済み。正式能力入力は接続・検証中。正式値がない情報を仮値で補完して完成扱いしない。

## 残項目と完了条件

上から順に進める。各PRは登録→必要な承認・確定→計算／参照→画面・Agent→業務経路検証を可能な範囲でまとめる。Backend / Frontend / 内部部品だけで機械的にPRを区切らない。

| 残る工程 | 具体的に残っているもの | 完了条件 | 状態 | 概算PR |
|---|---|---|---|---:|
| 能力・需要・条件付き復旧期限 | 製品候補選択、能力・負荷・互換性・bufferの登録／訂正、能力差・UNKNOWN・期限を画面とAgentへ接続 | BS-05・06・13の数値、別manager承認・確定、未知の維持を実PG・実モデル・実ブラウザで確認 | #248実装・検証中。B03・能力B07確定 | 1（#248） |
| 安全条件・リスク | 観測情報・安全基準・継続条件の出典付き正式入力、Hard Constraint、不明・除外理由・残存リスクの表示と更新時検証範囲 | BS-03・04・11、UC-B04等の業務受入。経済・能力から安全を推測しない | 未実装。B04・安全B07の判断が必要 | 1〜2 |
| 対応計画・故障履歴 | 修理／交換／継続案、作業時間と調達lead time、次回保全／将来予約の意味、故障・修理・過去損失の登録・参照 | BS-07・12・G01、UC-B06〜08・12・14。STOPPEDから故障原因を生成しない | 未実装。B05・B06・対象B07の判断が必要 | 1〜2 |

| 回答品質・全業務総合受入 | 正式入力を統合したDecision Package、全BS / Goldenの固定fixture・未知・拒否、一般LLM／検索品質、全対象UI経路の不足修正 | business-scenariosとACに照らして未実装・BLOCKED・未検証を解消。実データ出典・入力前提を追跡可能 | 一部既存Read検証済み。正式入力統合と全BSは未受入 | 2〜3 |

| **残り合計** | **本PRを含む業務機能と受入** | | | **6〜11（中心8〜9）** |

これはPR粒度を業務経路へ再集約した概算であり、残作業が減ったという意味ではない。PO判断・受入不具合で変更が必要なら根拠を示す。対象内の機能や必要な検証を削って数を合わせない。経済入力の完了を全Decision Packageの完成へ拡大しない。

## 完了を判断する基準

- 対象業務機能が正式入力から利用でき、未登録値をモックで補完しない。
- 全Business Scenario / Goldenと対応ACの未実装・BLOCKED・未検証を解消する。
- 画面・Agent・権限・承認・確定・競合・監査・復旧を、変更の影響に必要な実環境で検証する。
- Graph到達や構造代替と、実際の停止・能力・安全・納期保証を混同しない。
- 現在登録情報の期間評価を、過去状態の完全復元と説明しない。
