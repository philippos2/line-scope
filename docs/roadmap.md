# LineScope 開発ロードマップ

仕様の正本は[文書入口](deliverables.md)で選ぶ。現在はPR #265後のブラウザ指摘を整理し、画面の導線と入力・変更操作を直す計画のレビュー段階。

## 現在地と残PR

- PR #263・#264・#265はmerge済み。シナリオ1の設備検索・関係図・損害額・代替提案の実装と検証を行った。
- 5174番のLLM接続は復旧し、設備コードを含む質問への実応答を確認済み。質問対象の引継ぎ・原因別エラー表示は残る。
- **PR #266は文書のみのDraft。実装着手は禁止されており、明示命令を待つ。**
- **残る実装は基本2 PR、概算4〜6作業日。** #266は別に数える。レビュー・CI・利用者確認の待ち時間は日数外。
- 未調査部分でAPI等の追加変更が必要なら、追加1 PRの可能性がある。現時点で必要とは確定しておらず、原因・影響・工数を報告してから判断する。

原因・修正方法の把握状況は[計画文書§1.1](design/post265-ui-correction-plan.md#11-原因と修正方法をどこまで把握しているか)に一覧化する。特に**候補付き入力の取得方法と、変更・承認・実行の具体的な無効原因は未確定**。

## 残項目と割当

| 工程 | 対象 | 状態 | 想定PR | 工数目安 |
|---|---|---|---|---|
| 計画レビュー | 指摘・配置・対応順・見積もり | 文書作成、レビュー待ち | #266（文書のみ） | 実装日数外 |
| 画面入口と対象設備の接続 | 上部6タブ、接続及び影響範囲への改称、比較・文書検索、共通比較期間の日時選択、質問対象とエラー表示 | 未着手 | 実装A：1 PR | 2〜3作業日 |
| 入力と変更手続きの完走 | 4カテゴリの候補付き入力、無効ボタン調査、変更準備・承認・実行の導線と理由表示 | 未着手・候補取得元と原因に未調査部分あり | 実装B：1 PR | 2〜3作業日 |
| 条件付き追加 | 既存APIでは足りない取得機能や契約外の問題が判明した場合 | 必要性未確認・未承認 | 追加C：必要なら1 PR | 影響調査後に見積もり |
| 利用者確認 | 各PRの最新版を5174番で操作 | 各実装後 | A/B内、別PRにしない | 待ち時間は別 |

項目別の対応は[画面修正項目・対応計画§8](design/post265-ui-correction-plan.md#8-想定pr工数と依存関係)を参照する。現在の基本計画は2 PR、追加が必要な場合は2〜3 PRの見込みだが、未調査の追加範囲を確定工数とは扱わない。
