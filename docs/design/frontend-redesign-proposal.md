# 設備探索・関係図・損害額のUI再設計案

**状態：設計レビュー待ち。実装承認ではない。** 本書はClaudeと開発依頼者による評価用であり、現行画面を説明する文書ではない。Frontend・Backend・データ・稼働サービスの変更はこの設計作業に含めない。

## 1. 目的と文書の位置づけ

LineScopeは、設備単体の状態を並べる画面ではなく、設備・工程・生産作業・製品・インフラの関係から、依存先と影響範囲を調べるライトウェイト・オントロジーシステムである。主画面は次の順序を一つの画面で支える。

1. 名称やコードから設備を探す。
2. 選んだ設備のつながりと、停止した場合に影響を受け得る先を図で調べる。
3. 登録条件に基づく時間当たりの損害額を確認する。

**成功の基準：初めて使う人が、説明を受けずに設備名の一部を入力し、候補を選び、関係図と損害額の状態を確認できる。** 算定データがない場合も図を調べられることを必須とする。

比較・出典・入力登録・変更承認・質問は、上記の調査から必要に応じて開く補助機能とする。自動異常検知、Incident一覧、工場全体の損害額集計、架空の状態・KPI、自動修理・制御は追加しない。

## 2. 現行の問題と変更方針

| 現行 | 利用者に起こる問題 | 変更方針 |
|---|---|---|
| 経済入力検索を設備探索の入口に使用 | 算定データのある設備だけが突然出る | 設備検索を唯一の入口とし、算定データは設備選択後に調べる |
| 二つの調査モード | つながりと金額を行き来し、依存先の調査が見つからない | 一画面に統合する |
| 設定を揃えて一括調査 | 何を選ぶべきか分からず、関係図に到達できない | 最初の設備選択ですぐ関係図を取得する |
| 取得直後に最大30件の属性参照 | 表示待ちと要求が増える | 属性はノード選択時だけ取得する |
| 複数起点をまとめて全体の直接／間接を表示しようとする | サーバが判定していない分類を作る危険 | 直接／間接は起点別に表示する |
| 生の列挙値・内部用語・同じ注意書きの反復 | 利用者の問いより実装事情が前面に出る | §8の用語と状態別文言へ統一する |

M-204・M-208は受入データの例に限る。設備コード・台数・金額に応じた特別分岐や専用文言は作らない。

## 3. 画面構成

### 3.1 広い画面

```text
┌ LineScope                          接続中の利用者／接続設定 ┐
│ 設備を選んで、止まったときの影響と損害額を調べる             │
├ 左：設備を探す ┬ 中央：つながりと影響の範囲 ┬ 右：選択した項目 ┤
│ 名前・コード   │ [影響を受ける先][依存する先]│ 名称・種別       │
│ [        ][検索]│ 起点別の要約／調べた範囲    │ 登録属性・状態   │
│ ☑ 名称／コード │                            │ 選択ノードを含む │
│   算定データ…  │       関係図               │ 経路             │
│ ☐ 名称／コード │   起点を強調／共有先を表示  │ 比較へ進むボタン │
│ 選択解除       │ [一覧から項目を選ぶ]        │                 │
│                ├ 推定損害額（円／時間）─────┤                 │
│                │ 金額または理由／内訳／詳細 │                 │
├────────────────────────────────────────────┤
│ 質問する／対応案を比べる／出典と経路／入力を登録・訂正／変更・承認・実行 │
│ 選択した補助パネル（初期状態では内容を開かない）               │
└────────────────────────────────────────────┘
```

金額パネルは中央列の関係図の直下に固定配置する。補助パネルの開閉・タブ切替で消さず、図だけを画面高いっぱいに広げて金額を押し出さない。1600px時の目安は左240px・右300px・残りを中央、図の高さ360〜480px。実装時のスクリーンショットで見やすさを評価し、寸法だけで合格としない。

### 3.2 狭い画面

- 1000px未満は検索→関係図→損害額→選択項目→補助機能の縦順。768pxでも同順とする。
- 390pxでは検索候補を折りたためるが、選択設備の名称と選択解除を残す。
- 図には拡大・縮小・全体表示、同じ項目を選べる一覧を併設する。ページ自体に横スクロールを出さない。
- 補助パネルを開いた際のみその見出しへフォーカスを移す。「関係図に戻る」を置き、選択と図を保持する。

## 4. 操作の流れ

| 段階 | 利用者の操作 | 画面の反応 | 自動で行わないこと |
|---|---|---|---|
| 初期 | 名前・コードを入力して「検索」 | 候補を表示。空欄検索も可能 | 経済入力から設備候補を作らない |
| 最初の選択 | 設備のチェックを入れる | その設備の下流・上流を取得。下流を初期表示。算定データ検索も独立開始 | 比較対象の変更、変更準備 |
| 追加選択 | 別の設備も選ぶ | 選択集合に対応する図を表示。共有到達先を識別 | 金額のブラウザ合算、全体の直接／間接推定 |
| 図を読む | 下流／上流の切替、ノード選択 | 選択ノードの属性を取得し、そのノードを含む返却経路を強調 | 属性の全件先読み、上流を下流影響と呼ぶこと |
| 金額を見る | 1件なら操作不要、複数なら算定データを選択 | 条件が揃えばサーバ算定。不足なら理由と登録操作 | 未選択を最新版と推測、期間の勝手な変更 |
| 対応を考える | 設備を確認して「この設備で対応案を比べる」 | 対象を明示して下段パネルを開く | ノード選択だけで比較・入力対象を変更 |
| 変更後 | 更新を試行し、調査へ戻る | 取得済み結果を更新前と表示。「再調査」で更新 | 自動実行、状態変更だけによる回復認定 |

検索候補の上限・複数選択の上限はサーバ契約に従う。損害額APIは最大10設備のため、主画面も選択上限10件とし、上限到達時に理由を示す。候補に続きがある場合のみ「ほかにも設備があります。名前やコードで絞り込んでください。」と案内する。

## 5. 関係図の設計

- 設備・工程・生産作業・製品・インフラを色と種別名の両方で区別する。起点は枠と「選択設備」で強調する。
- 初期表示は「止まると影響を受ける先」。切替先は「この設備が依存する先」。片方の失敗をもう片方の成功と混同しない。
- 一台選択時の要約は「直接 N件・間接 M件／調べた範囲：最後まで調べた」。値はサーバ分類を使う。
- 複数選択時は起点別の直接／間接件数を並べる。ある先が設備Aには直接、設備Bには間接の場合、両方を表示する。全起点を合算した直接／間接件数は作らない。
- 「共有する影響先」は、複数の下流結果の返却到達集合に同じ種別・IDがある項目の表示上の照合。上流の共通依存分析とは区別する。未探索範囲まで共有なしとは判断しない。
- 経路・辺は返却されたものだけを描く。図の併合は新しい経路・代替成立・業務判断を生成しない。
- 起点を含む選択集合の結果で世代が一致しない場合は一つの正常図に合成せず、再取得を案内する。時点の異なる正本と図を同時Snapshotとは説明しない。
- 非最新・再構築中の場合、旧図を正常表示しない。図領域を理由と再試行に置換し、検索と算定条件は保持する。算定APIも図に依存するため金額は有効な値として残さない。
- 正常な探索で関係がない場合は「登録されたつながりはありません」。探索不完全時に同じ文言を使わない。
- 描画上限で省略した場合は、サーバ探索の制限と区別して「図では一部を省略しています」と示す。一覧・起点別表示で確認できる導線を置く。
- 凡例の注意書きは一行：「つながりをたどった結果です。実際に止まるとは限りません」。

### ノード属性とキーボード

選択時にのみ対象種別の属性を取得する。同じID文字列でも種別の違うレコードの属性を流用しない。属性失敗時も図を残し、右欄だけに再試行を置く。名称が未取得なら「工程（名称を確認）」等の種別表示とし、UUIDを名前の代わりに露出しない。

検索欄→検索ボタン→候補チェック→方向切替→ノード一覧の順にTab移動できる。一覧のEnter操作を図のノード選択と同じ処理にし、右欄の更新を通知する。取得完了だけでフォーカスを奪わない。

## 6. 損害額の状態と算定データ

算定データ検索は選択設備のIDと一致する登録値だけを採用する。現行検索filterのequipment_queryは名称・コードの絞込みであり、一致する別設備を混入させない。ページ取得が完了していなければ「なし」「1件だけ」と確定しない。必要なページ取得または絞込みに失敗した場合は「確認できません」と表示する。

| 状態 | 主表示 | 次の操作 |
|---|---|---|
| 設備未選択 | 設備を選ぶと表示されます。 | 設備を探す |
| 登録有無を取得中 | 算定データを確認しています… | 図の調査を続けられる |
| 登録なしを確認 | この設備には損害額の算定データが登録されていません。 | 「算定データを登録する」で対象設備を明示して入力へ |
| 一件 | そのデータを自動選択して算定 | 詳細から期間・出典を確認 |
| 複数件 | 損害額の算定データを選んでください。 | コード・版・適用期間・出典を併記して選択 |
| 選択設備間で期間不一致 | 期間が違うため、合計できません。 | 対象別の期間と選択を表示し、共通期間を指定する |
| 算定中 | 算定しています… | 図を操作できる |
| 全項目算定済み | ○○ 円／時間・すべて算定済み | 内訳へ |
| 一部不明 | 判明分のみ ○○ 円／時間（不明あり） | 設備別の不足理由と登録・訂正操作 |
| 取得失敗 | 原因に対応した文言 | 金額だけ再試行。図は保持 |
| 更新試行後 | 更新前の結果です。再調査してください。 | 旧額を現在額として表示せず、再調査 |

複数設備のうち一部の算定データがない場合も、他設備を画面の選択から除かない。期間を決められれば選択設備全体と取得済みの入力をサーバへ送り、部分結果を表示する。全設備で登録なし・期間未定なら算定要求は送らず、理由を表示する。

- 金額はAPIの十進文字列を整形するだけ。加算、重複排除、円換算、累積額算出をFrontendへ持ち込まない。
- 内訳は対象設備・影響製品・共有範囲の計上／重複のため除外・出典・式を折りたたみに置く。版は選択時と詳細では表示してよい。
- 評価期間は最初に選んだ算定データから初期設定し、詳細で変更できる。他の期間を自動的に一致扱いしない。
- 算定結果に含まれる図と、画面の図の世代・選択が違う場合、その対応が確認できるまで同じ調査の金額として並べない。再調査を案内する。
- 一行の注意書き：「登録された条件での見積もりです。実際の損害額ではありません。」

**重要な契約上の制限：現行APIは登録状態が停止中の設備に適用する推定である。稼働中設備を仮想的に停止させる入力はない。** したがって「稼働中の設備が止まった場合の金額」を現行API値から作らない。画面全体の見出しとこの制限の整合は§10のレビュー事項とする。

検索結果のバッジは「算定データあり／なし／確認中／確認できません」の四状態。設備検索を待たせず候補を先に表示し、選択後の確認結果を反映する。全候補のバッジ確定のために一斉詳細取得はしない。検索時点で全候補に有無を確定表示する要件を採る場合、取得手段を別途合意する。

## 7. データ経路・状態管理・責務

### 7.1 取得経路

| 用途 | 経路と契約 | 依存させないもの |
|---|---|---|
| 設備検索 | searchEquipment(query)へ閉じ込める。実経路は§10のA／B／Cが未決 | 算定データ、自然文の自由生成 |
| 下流／上流 | POST /agentの厳密な「関係分析 {JSON}」。target等はapi-toolsに従う | 算定データの登録・選択 |
| ノード属性 | 同じ直接経路で対象種別のget_* | 全ノードの事前取得 |
| 算定データ | POST /economic-inputs/searchとGET /economic-inputs/{id} | 関係図の描画成功 |
| 損害額 | POST /incidents/investigate。選択設備・入力・共通期間を送る | Reactでの集計 |
| 共通依存・代替・弱点 | 既存の直接分析を「詳しい分析」に残す | 自由な経路生成 |
| 比較・登録・承認 | 既存パネルと契約を維持 | 主画面表示の前提にしない |

### 7.2 画面内の状態

検索結果、調査対象集合、ノード選択、比較・入力対象、表示方向、算定条件、更新世代を別の状態として持つ。ノード選択を比較対象の変更に結び付けない。

- 対象集合が変わったら旧図・旧額・旧属性を消す。比較対象が集合から外れた場合は比較・入力・変更下書きも破棄する。
- 追加選択で既存の比較対象が残る場合は、その明示対象を維持する。起点追加だけで入力中の内容を破棄しない。
- AbortSignalと要求番号に加え、対象集合・期間・方向・更新世代を応答受理時に確認する。条件変更前の応答を復元しない。
- 下流、上流、算定データ、損害額、属性は取得中・失敗を独立管理する。新しい検索の失敗だけでは既に選んだ設備の正常図と金額を消さない。
- 更新実行試行で取得結果を更新前扱いにする。応答不明を「変更済み」と断定しない。承認だけでは更新前にしない。
- 再取得中に別更新が起きた場合、その取得結果で更新前表示を解除しない。
- 接続解除・利用者切替ではすべて破棄する。tokenはURL・storage・ログへ保存しない。

### 7.3 コンポーネント案

| 責務 | 提案する単位 | 境界 |
|---|---|---|
| 接続・全体組立 | App | 認証と共有更新世代、明示した補助操作の引継ぎ |
| 設備検索・選択 | EquipmentSearchPanel | 設備API結果の表示と選択。算定根拠で候補を絞らない |
| 読取要求の管理 | useEquipmentInvestigation | 対象・方向・要求番号の整合。業務計算をしない |
| 図・一覧・凡例 | GraphWorkspace／既存描画部品 | 返却経路の表示と選択 |
| 属性・選択経路 | SelectedNodePanel | 選択時取得。対象型とIDの一致を確認 |
| 算定条件・結果 | LossEstimatePanel | 入力選択、期間、サーバ値・理由の表示 |
| 既存業務操作 | 補助パネル群 | 比較・出典・入力・変更承認の契約維持 |
| 表示用語 | 表示マッピング | 内部値→日本語。未知コードは安全な一般文＋技術情報 |

これは分割の案であり、空の汎用基盤や形式だけのInterfaceを増やさない。既存部品を再利用する範囲は実装承認後に差分で確認する。

## 8. 用語・エラー・注意書き

| 現行語・内部語 | 通常表示 |
|---|---|
| 被害額・停止損失（調査金額） | 推定損害額（円／時間） |
| 経済入力・正式入力・損失根拠 | 損害額の算定データ |
| Graph／グラフ | 関係図 |
| 探索の完全性 | 調べた範囲 |
| 影響候補 | 影響を受ける先 |
| 調査・回答／問い合わせ | 質問する／送信／回答 |
| 根拠を確かめる | 出典と経路 |
| CURRENT | 最新の関係で表示しています |
| complete=false | 途中まで（制限あり）。理由も日本語で表示 |
| SPOF | 止まると全体が止まる部分（単一障害点） |
| version | 版 |
| 設備カードの状態変更 | 「変更・承認・実行」内の「登録状態を変更する」 |

修理案比較の仮想停止費用は調査金額と同一視せず、「修理中の損害額見積もり」等、評価対象が分かる名称にする。サーバの安全判断・UNKNOWN・未評価は意味を変えず日本語表示する。

| 原因 | 表示と操作 |
|---|---|
| 接続切れ／認証切れ | 接続が切れました。接続し直してください。／接続設定 |
| 権限不足 | この情報を表示する権限がありません。／権限を広げず他の表示は保持 |
| Graph非最新 | 関係データの更新待ちです。／再試行 |
| 再構築中 | 関係データを再構築中です。／再試行 |
| 接続先・依存サービス停止 | 情報を取得できませんでした。／対象領域だけ再試行 |
| 期間・入力不一致 | 期間または選んだ算定データを確認してください。／該当設定へ |
| 未知のエラー | 情報を取得できませんでした。／再試行＋技術情報 |

原因がサーバで区別されない場合は推測で原因を断定しない。「技術情報」の折りたたみ内にのみエラーコード・ID・生の列挙値を出す。出典の原文や利用者が入力した名称は勝手に改変しない。

通常のUIラベルにGraph、Envelope、Tool、state_code、UUID、生の列挙値、APIエラーコード、正本、SPOF、経済入力、被害額、損失根拠を出さない。外部文字列内の同じ語を誤検出して内容を隠さないよう、自動検査はアプリが生成するラベルと制御した受入データを対象にする。詳細を閉じた通常DOMと、補助パネルを開いた状態を確認する。

注意書きは、損害額の一行、図の凡例の一行、不完全・不明時の必要な警告に絞る。「工場全体を網羅していません」を各欄で繰り返さない。LLM待ち時間の注記は質問・文書検索の操作時だけに表示する。

## 10. 判断待ち・レビューしてほしい点

### D1：設備検索の非LLM経路（開発依頼者が決定）

| 案 | 内容 | 影響 |
|---|---|---|
| A | 「関係分析」の許可リストへsearch_equipmentを追加 | 新HTTP APIなし。api-tools・認可・直接経路の検証が必要。差分量は実装前に確認 |
| B | 現状の自然文LLM経由 | 「画面表示取得は自然文LLMを使わない」およびUA-04に適合しない。採用時は要件の再判断が必要 |
| C | 設備検索の専用API | 現行のTool個別HTTP公開方針との整理・契約追加が必要 |

未決のままAを実装しない。設計上のsearchEquipmentの責務だけを確定候補とする。代替実装の画面を実接続済みと報告しない。

### D2：停止した場合の仮想金額と現行算定の差

現行incident算定はRUNNINGを停止損害の適用対象から除き、STOPPED以外の不明状態は条件未確認にする。全設備について仮想停止時の金額を示すAPIではない。

本案の推奨は、当面は図で仮想の到達範囲を見せ、金額には「登録状態に基づく算定」と明示すること。稼働中設備の0が返っても「停止しても損害がない」と説明せず、仮想停止の金額は未評価と伝える。全設備の仮想停止金額を必須にするなら業務条件・APIの追加設計が必要。見出しを含め、この落とし所をレビューで確定する。

### D3：候補すべての算定データバッジ

現行設備検索に登録有無の一括属性はない。候補表示を止めず、未選択は未確認、選択後に有無を表示する本案が指示書の意図を満たすか確認する。常時確定バッジが必須なら、検索結果の網羅性・取得負荷を含めた別の取得設計が必要。

### D4：複数起点の分類と図・金額の整合

起点別の直接／間接分類と、返却集合で照合した共有先の表示で理解できるか。世代不一致で再調査を求める設計、金額を図の直下に置く配置が、目的の理解と操作を妨げないかを確認する。
