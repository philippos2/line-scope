# 技術検証デモ：質問欄だけの登録情報照会

## 目的・制約・完了判定

目的は、固定した9観点の質問に、検索層の共通照合・型付きRead・Evidence・コードの定型文で直接答えること。質問のUIは既存テキストボックスと送信操作だけ。確認も同じ会話に返信し、観点パネル・候補ボタン・H6確認・LLM分類/生成は追加しない。独立した設備一覧・Graph・比較等は維持する。

開発者は2026-10-26に計画①〜⑧、自動40（Backend36/Frontend4）、直接API138、ブラウザ4と既存主シナリオを承認した。新しい観点・語彙の拡張、試験追加、複雑な構文が必要なら停止して判断を求める。実モデル・DB/seed/認証/設定変更は不要。新PR1本・Draft、mergeは開発者が行う。

## 実装前に固定した9観点

| key | 定義 | 代表語彙・表現 |
|---|---|---|
| registered_state | 登録された運用状態。現在の実稼働の保証ではない | 登録状態、稼働状態、動いているか、止まっているか、いま死んでるか |
| downstream_reachability | 登録関係の下流到達。実停止を断定しない | 停止の影響範囲はどこまでか、止まるとどんな影響があるか |
| upstream_dependencies | 登録上の上流依存先 | 何に依存しているか、上流の依存関係 |
| alternative_candidates | 構造上の代替候補。実運転可否ではない | 代替候補、代わりになる設備 |
| maintenance_records | 登録済み保全実績・実施日時。未記載の原因診断ではない | 保全記録、メンテナンス記録、前回のメンテナンス日時 |
| maintenance_plans | 登録済みの保全予定 | 保全計画、メンテナンス予定 |
| equipment_name | 登録設備名称 | 設備名、登録されている名称 |
| equipment_code | 登録設備コード | 設備コード、設備番号 |
| equipment_type | 登録設備種別 | 設備の種類、設備種別 |

対象部分以外の全文を照合する。一般の名詞照会の末尾（は/は何か/を教えて/を教えてください）と疑問符は共通に扱う。対象を除いた未説明部分、否定、修飾、複合質問を捨てて一致扱いしない。例文・語彙はカタログデータで管理し、質問/設備ごとのif文は作らない。語彙の記録・育成、LLMによる言換えは運用案にとどめ実装しない。

## 検索と近い候補

コードはNFKC・大小文字・空白・許可したハイフン類/アンダースコアの省略で照合する。数字・先頭ゼロは維持。名称はNFKC・大小文字・序数の整数表記を共通照合し、第1と第11を混同しない。同じキーが複数IDへ当たれば会話で選択を求める。

非一致の近いコード候補は、同じ正規化をしたコードのLevenshtein編集距離1以内（挿入/削除/置換各1）、距離・コード順で最大5。意味類似・未登録の別名・候補の自動採用なし。探索不完全は表示する。別名は将来登録IDに対応するレビュー済みデータで管理する案とし、今回DB/投入/編集UIを追加しない。

## 会話と安全境界

一意な対象と単一観点の全文一致なら確認なしで取得する。対象が複数なら名称・コードを本文へ列挙し、同じ欄で返信を求める。context_idのowner/TTLを既存機構で確認し、選択対象を再取得する。対象省略はコードを尋ねる。観点が不明/複数/未対応なら、何を識別できたかと、対応していない原文の内容、対応する質問例を示す。電話番号をメーカーや担当者へ置換しない。

0件は登録なしとして答え、未実施・実在しないと断定しない。取得障害・不完全・Evidence不整合は未登録と区別する。本文・facts・公開tool_resultsに、未選択属性・誤対象・根拠不整合の値を出さない。登録状態には必ず『登録上』の限定を付ける。

## 検証計画

自動40：検索同一性10、正常9観点、拒否境界8、状態/権限/Evidence9、UI4。再利用を含めBackend36/Frontend4、main既存回帰は別。全直積ではなく同値分割・境界・最小対を使う。直接APIは固定fixture46問各3回=138。内訳は旧原文33+新報告2=35、保留4、表記7。既知の誤受理5回は原文2種類の5応答で、二重計上しない。実モデルは使わない。

Safetyは別観点の公開0・根拠外事実0・空検索による不存在断定0。Livenessは対応観点の直接回答と表記の同一性、未登録/対応外の丁寧な案内。UIは専用選択パネルなし。Usabilityの拒否/案内/直接回答の頻度は別集計し、根拠のない正解率目標を追加しない。

## 暫定対応台帳

現時点の暫定特例は0。固定9観点と代表表現はこのデモの恒久的な対応範囲であり、意味理解全般の達成とはしない。追加が必要なら理由・範囲・終了条件とともに承認を求める。

## 代替候補の回答本文

代替候補は、Graph結果の除外対象・候補ID・構造成立・登録状態による利用可能性に対応させ、既存の設備Readで確認した名称とコードを本文へ出す。構造不成立・利用不可・不明・探索不完全を区別し、実際の代替運転は未評価と同じ塊で示す。候補名は先頭12件まで、省略を明示する。名称取得・Evidence不一致は候補0件に置換しない。質問欄では下流・上流を含め別の構造化表示へ回答を委ねる文を出さず、他の機械Read向けrendererの既定表示は維持する。
